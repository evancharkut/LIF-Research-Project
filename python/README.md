# Python port

A one-for-one translation of the MATLAB code in the repository root, kept here
so the results can be reproduced without MATLAB or the Signal Processing
Toolbox, and so the figures in `figures/` can be regenerated by anyone.

| Python | MATLAB |
|---|---|
| `lif.Params` / `lif_params()` | `lif_params.m` |
| `lif.lif_run()` | `lif_run.m` |
| `lif.fI_theory()` | the analytic block inside `lif_fI_curve.m` |
| `lif.filtered_noise()` | `filtered_noise.m` |
| `lif.spike_events()` | `spike_events.m` |
| `lif.spike_bits()` | `spike_bits.m` |
| `lif.spike_entropy()` | `spike_entropy.m` |
| `lif.shift_trials()` | `shift_trials.m` |
| `check_entropy.py` | `check_entropy.m` |
| `make_figures.py` | `lif_dc.m`, `lif_fI_curve.m`, `lif_filtered_noise.m`, `lif_jitter_reliability.m`, `lif_information.m`, `make_figures.m` |

Argument order, defaults and variable names follow the `.m` files so the two
can be read side by side.

## Running it

Needs NumPy, SciPy and Matplotlib.

```bash
python3 python/make_figures.py
python3 python/check_entropy.py
```

`make_figures.py` takes about 25 s — most of it the 128 frozen-noise trials the
noise entropy needs — and writes all six PNGs into `figures/`, printing the same
summary lines the MATLAB scripts print. `check_entropy.py` takes a few seconds
and checks the entropy estimator against trains whose answer is known.

## What agrees, and what cannot

The deterministic results are identical to the MATLAB ones, which is the point
of checking:

| quantity | MATLAB | Python |
|---|---|---|
| rate at I = 2 nA | 52.0 Hz (analytic 52.4) | 52.0 Hz |
| silent at 1.49 nA, fires at 1.51 nA | yes | yes |
| max f-I error above rheobase | < 1.6 Hz at dt = 0.05 ms | 1.73 Hz |
| f-I error at 10 nA, dt = 0.05 -> 0.002 ms | 1.4 -> 0.03 Hz | 1.40 -> 0.035 Hz |

The noise-driven results cannot match sample for sample: NumPy's generator is
not MATLAB's, so `rng(1)` and `default_rng(1)` produce different stimuli. The
frozen-noise raster and the leak sweep therefore agree statistically — same
rates, same jitter and reliability to within the sampling error of 10 trials —
but not point for point.

Two smaller differences, both deliberate:

- `filtfilt` pads by `3*(nfilt-1)` samples here, to match MATLAB's default
  rather than SciPy's.
- MATLAB's `std` normalises by `N-1` and returns 0 for a single sample; NumPy's
  default normalises by `N` and returns `nan`. `spike_events` uses `ddof=1` and
  special-cases the one-spike event, so single-spike events report zero jitter
  as they do in MATLAB.

## The entropy code

`spike_entropy` is the one piece where the Python and the MATLAB are not a
line-for-line transcription, though they compute the same thing by the same
route. MATLAB's `accumarray` and NumPy's `bincount` fill the same role in the
per-column entropy, and the group-size trick is identical: each of the `c`
members of a group of identical words contributes `-(1/n)*log2(c/n)`, so summing
over elements rather than over groups gives `-sum(p*log2(p))` with no loop over
words.

The information figure is noise-driven, so like the raster and the leak sweep it
agrees with MATLAB statistically rather than sample for sample. The quantity that
should agree is the answer: about 100 bits/s and 3.3 bits/spike, within the ±5%
the fit range and bin width are worth.

## The extra figure

`figures/dt_convergence.png` has no MATLAB counterpart. It plots the claim in
the main README that the residual f-I error is threshold-crossing quantisation
rather than integration error: the crossing is only detected at the end of a
step, so every ISI is biased upward by up to one `dt`, a fixed *time* error that
costs `rate^2 * dt/1000` Hz and therefore hurts proportionally more at a high
rate. The measured errors sit under that bound at both currents, and the 10 nA
curve sits roughly an order of magnitude above the 2 nA curve at every `dt`,
which is the `rate^2` scaling.

Measuring the rate from the spike count would not show this. Counting spikes
over a 2 s window quantises the rate to 0.5 Hz, which is larger than the effect,
so the figure measures the rate from the mean inter-spike interval instead. The
staircase plateaus that remain are the residual quantisation of the ISI itself
into a whole number of steps.
